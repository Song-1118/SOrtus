# SOrtus 界面设计方案（UI Design Spec）

> 版本：v1.0 · 2026-10-23
> 适用阶段：MVP 0.1.0（工程骨架 + 架构 + 视觉基础）及后续迭代
> 上游依据：《产品需求文档》第六章、《项目开发规范》第七章、`Resources/Themes|Styles` 已落地资源字典
> 许可证：MIT

## 一、设计概述

### 1.1 设计目标

SOrtus 是"本地优先的立项管理工具"。界面设计围绕三个关键词展开：

| 关键词 | 设计含义 |
| --- | --- |
| **立项** | 以"卡片"为信息单元，列表一眼概览，详情分区沉淀 |
| **本地** | 安静、可控、无干扰；磨砂玻璃营造"悬浮于桌面"的轻盈感 |
| **现代** | 高斯模糊、圆角、缓动动画，Windows 11 原生质感 |

### 1.2 设计原则

1. **一个范式管三类**——编程 / 剪辑 / 待办共用同一套导航、卡片、表单与反馈模式，仅字段与语义色不同，把学习成本压到零（PRD 3.1）。
2. **样式先集中，页面零细节**——所有模糊、圆角、动画、色值只存在于全局资源字典，页面只引用（规范第七章）。
3. **磨砂只做层次，不做噪音**——模糊只作用于侧边栏、内容卡片、弹窗遮罩三类容器；列表项永不单独模糊（规范 7.7 性能红线）。
4. **状态可见，操作有底**——空状态、加载、错误、未保存、删除确认均有明确界面反馈（PRD 5.5）。
5. **键盘可达，对比达标**——Tab 顺序合理，正文对比度 ≥ 4.5:1（PRD 6.3 / 第七章可访问性）。

### 2.2 立项类型色（本方案新增约定）

三类立项各占一个强调色，全应用一致，做到"扫颜色即分类"：

| 类型 | 主色 | 浅色主题标签底 | 深色主题标签底 |
| --- | --- | --- | --- |
| 编程开发 | `ColorAccentA` 靛紫 | `#EEEDFE` | 靛紫 25% 透明 |
| 剪辑 | `ColorAccentC` 粉 | `#FBEAF0` | 粉 25% 透明 |
| 待办 | `ColorAccentB` 天蓝 | `#E6F1FB` | 天蓝 25% 透明 |

### 2.3 项目状态语义（ProjectStatus → 视觉映射）

| 状态 | 建议用色 | 标签文案（中） |
| --- | --- | --- |
| Planning 规划中 | 灰 `#5F5E5A` | 规划中 |
| Active 进行中 | Info 蓝 | 进行中 |
| Completed 已完成 | Success 绿 | 已完成 |
| OnHold 已暂停 | Warning 橙 | 已暂停 |
| Archived 已归档 | 灰（弱化） | 已归档 |

> 改进点：现状标签为"实色底 + 白字"，12px 白字在 `#6366F1` 上对比约 3.9:1，未达 AA。本方案统一改为**浅色主题"浅底深字"、深色主题"半透明同色底 + 亮字"**，对比度全部 ≥ 4.5:1。

### 2.4 字体排印

| 项 | 值 | 说明 |
| --- | --- | --- |
| 字体族 | `Microsoft YaHei UI`，回退 `Microsoft YaHei`、`Segoe UI` | Windows 10/11 原生中文 UI 字体 |
| 字号阶梯 | 11 / 12 / 13 / 14 / 15 / 16 / 18 / 22 / 28 | 11=脚注，12=标签，14=正文，15=列表主标题，22=页标题，28=品牌 |
| 字重 | Regular 400 / SemiBold 600 | 仅两档；标题与数字用 SemiBold |
| 行高 | 正文 1.5，多行输入 1.4 | — |

### 2.5 间距 / 圆角 / 阴影（`Styles/Sizes.xaml`）

- 间距：4px 基距，档位 Xs4 / Sm8 / Md12 / Lg16 / Xl24。
- 圆角：Small6（输入框、小按钮）/ Medium12（卡片、按钮、弹窗）/ Large18（窗口、大面板）/ Pill999（标签、胶囊按钮）。
- 阴影：`ShadowBlur=24`、`ShadowOpacity=0.18`，仅用于卡片与弹窗的 Depth，不用于文字。

### 2.6 高斯模糊档位（规范 7.3，唯一来源）

| 档位 | 半径 | 用途 |
| --- | --- | --- |
| `BlurRadiusNone` | 0 | 关闭 |
| `BlurRadiusSubtle` | 6 | 轻层次：列表项选中态 |
| `BlurRadiusNormal` | 12 | 默认：侧边栏、内容卡片 |
| `BlurRadiusStrong` | 20 | 强：对话框 |
| `BlurRadiusOverlay` | 30 | 全屏遮罩（大面积，需渲染验证） |
| `GlobalBlurRadius` | 12 | 全局强度，设置页可调，改一处全应用生效 |

## 三、信息架构与导航

```
MainWindow（1180×760，壁纸 = 渐变 + 三色光斑）
├── Sidebar（248px，磨砂卡片，BlurRadiusNormal）
│   ├── 品牌区：SOrtus（28px SemiBold）+ 副标语"本地优先"
│   ├── 导航：立项列表 / 新建立项 / 设置
│   └── 底部：版本与 MIT 脚注
└── Content（视图容器，DataTemplate 驱动切换）
    ├── ProjectListView   立项列表
    ├── ProjectWizardView 立项向导（选择类型 → 填写信息）
    ├── ProjectDetailView 立项详情
    └── SettingsView      设置
```

**为什么是左侧导航**：与 Windows 桌面软件惯例（文件资源管理器、系统设置、VS Code）一致；三类立项 + 设置共四个入口，纵向导航在一屏内可完全展开，无需折叠菜单，符合"上手即用"目标（PRD 3.1）。

## 四、界面详细设计

### 4.1 立项列表（主界面，P0）

**布局结构**（自上而下）：

1. **页头**：左侧"立项列表"页标题 + 副标题"共 N 个立项"；右侧统计胶囊（全部 / 进行中 / 已完成，数字用 SemiBold）。
2. **工具栏**：搜索框（占主宽，占位"搜索立项名称…"）→ 类型筛选 → 状态筛选 →「＋ 新建」主按钮。
3. **列表**：`ListView` 外层为磨砂容器；**每一项是白surface 卡片，不带独立模糊**（规范 7.7）。
4. **空状态**：图标 + "还没有立项" +「创建第一个立项」主按钮（点击直接进向导）。

**列表卡片信息层级**（单行高约 64px）：

| 区域 | 内容 | 视觉 |
| --- | --- | --- |
| 左 | 项目名称 | 15px SemiBold，超长省略号 |
| 中 | 类型标签 + 状态标签 | 胶囊，浅底深字（2.2 / 2.3） |
| 中下 | 进度条 + 百分比 | 4px 圆角条，Primary 填充，仅编程/剪辑显示 |
| 右 | 更新时间（12px 次要色） | `更新于 10-23` |
| 右 | 「打开」次按钮 | 进详情 |

**用户习惯对齐**：搜索 + 双筛选 + 主操作按钮集中于顶部一行，是文件管理器 / 任务类工具的标准范式；卡片而非表格行，配合磨砂容器在信息密度与呼吸感之间取平衡。

### 4.2 立项向导（P0）

**两步式向导**（单屏内完成，不弹新窗口）：

- **第 1 步 · 选择类型**：三张大卡片横排——编程开发 / 剪辑项目 / 待办任务。卡片含类型图标（SVG 线性图标）、名称、一句话说明（"记录技术栈、规划与验收"等）。选中态：Primary 2px 描边 + 左上角勾选圆点。键盘：左右方向键切换、回车确认。
- **第 2 步 · 填写信息**：按 PRD 5.1–5.3 分类型呈现字段，已落地编程类型全字段：
  - 项目名称（必填，标签带红色 `*`，空值时保存按钮禁用并内联提示）
  - 技术栈：输入框 +「添加」按钮，已选项以可删除胶囊（×）呈现；预设多选 chips
  - 简介：多行输入（AcceptReturn）
  - 子类型：下拉
  - 关联文件夹：路径框 +「浏览…」按钮（OpenFileDialog 取目录）
  - 开发工期：起止两个 DatePicker
- **底部操作栏**：「创建立项」主按钮 +「取消」次按钮；错误信息以内联红字展示在按钮行右侧。

**用户习惯对齐**：把"选类型"独立成第一步，避免三类字段混在一屏造成认知负荷；必填项即时反馈（按钮禁用态 + 星标），而非提交后才报错。

### 4.3 立项详情（P0）

**两栏布局**（内容区 ≥ 760px 时）：

- **左栏（主，约 60%）**
  - 页头：返回按钮（←）+ 项目名（可编辑输入框）+ 类型/状态标签
  - 基础信息分区：简介、子类型、关联文件夹、技术栈
  - 过程管理分区（编程类型）：开发规划 / 开发约束 / 开发目标 / 验收标准，四个多行输入，分区标题 14px SemiBold + 次要色，分区间 24px 间距
- **右栏（约 40%）**
  - 进度卡片：大号百分比数字（28px SemiBold）+ 滑杆 + 进度条；改动即时可见
  - 元信息卡片：创建时间、更新时间（12px 次要色）
- **底部操作栏**：「保存」主按钮、「删除」危险按钮（点击弹二次确认对话框）、「返回」次按钮。存在未保存改动时，「保存」按钮旁显示"有未保存的更改"提示（PRD 5.5）。

**用户习惯对齐**：查看与编辑同屏（无需切换编辑模式），是 Notion / 任务详情类工具的主流范式；危险操作（删除）与常规操作在视觉上拉开距离（红按钮 + 确认弹窗）。

### 4.4 设置（P1）

分区卡片式排布，每区一个磨砂卡片：

1. **外观**
   - 主题：两张预览卡（浅色 / 深色），卡片内嵌迷你界面缩略示意；选中态 Primary 描边。切换即时全局生效（规范 7.8）。
   - 高斯模糊强度：滑杆，刻度标注档位名（关闭 / 轻微 6 / 标准 12 / 强 20 / 遮罩 30），实时作用于全应用磨砂控件并持久化（PRD 5.4.2）。
2. **语言**：中文 / English 两张选项卡；运行时切换、即时重建资源字典；预留韩/日扩展位（PRD 5.4.4）。
3. **数据**（1.4/1.5 版本占位）：导出 / 导入 / 备份恢复入口，本版置灰并标注"即将推出"。
4. **关于**：SOrtus 0.1.0 · MIT License · "本地优先，无网络请求"。

### 4.5 提醒通知（P6 预留）

待办到期时屏幕右下角浮动磨砂卡片：待办标题 + 截止时间 + 「标记完成」「稍后提醒」两个动作按钮；4 秒内不自动消失（桌面工具惯例），可手动关闭。

## 五、组件规范

| 组件 | 规格 | 资源位置 |
| --- | --- | --- |
| 主按钮 | Primary 底、白字、Pill 或 Medium 圆角、Padding 22,10；Hover 提亮 8% | `Controls.Button.xaml` |
| 次按钮 | 透明底、Border 描边、文字色 | `Controls.Button.xaml` SecondaryButtonStyle |
| 危险按钮 | Danger 底白字，仅删除/恢复用 | 详情页内联引用 `DangerBrush` |
| 输入框 | Medium 圆角、Border 描边、MinHeight 38、聚焦 Primary 描边 | `Controls.Base.xaml` |
| 下拉框 | 同输入框高度，内容垂直居中 | 同上 |
| 卡片（磨砂） | `BlurCardStyle`：Surface 底 + `BlurPanel.EnableBlur` + Medium 圆角 + 阴影 | `Controls.Card.xaml` |
| 对话框（磨砂） | `BlurDialogStyle`：Strong 档模糊遮罩 + Medium 圆角卡片 | `Controls.Dialog.xaml` |
| 标签 / 胶囊 | Pill 圆角、浅底深字、Padding 10,3 | `ViewTemplates.xaml` TagStyle |
| 进度条 | 4px 高、Pill 圆角、Primary 填充、200ms 缓动 | 详情页 |
| 列表项 | Surface 卡片、Border 1px、Medium 圆角、**无独立模糊** | `ViewTemplates.xaml` |
| 空状态 | 图标 + 文案 + 主按钮，居中 | 列表页 |

**入场动画**（`Animations.xaml`，仅 Opacity / Transform，禁动模糊半径——规范 7.7）：

- `FadeInOnLoad`：视图切换淡入 200ms
- `SlideUpOnLoad`：卡片 / 弹窗自下 12px 上移淡入 250ms
- 列表项增删：淡入淡出 150ms

## 六、交互与反馈规则

| 场景 | 规则 |
| --- | --- |
| 未保存离开 | 详情页有改动时点返回/导航，弹确认框：「有未保存的更改，是否保存？」 |
| 删除立项 | 二次确认对话框，明确写出立项名称；确认后删除并回列表 |
| 保存成功 | 底部轻提示（磨砂 Toast）「已保存」，2s 淡出 |
| 必填校验 | 名称空时：星标 + 按钮禁用 + 聚焦输入框 |
| 空状态 | 列表空、搜索无结果分别给不同文案；搜索无结果提供「清除筛选」 |
| 加载 | 首启迁移数据库期间显示 indeterminate 进度条（遮罩层） |
| 错误 | 内联红字（表单）/ 错误对话框（致命错误，如迁移失败） |
| 高风险操作 | 删除、导入覆盖、恢复备份一律二次确认（PRD 5.5） |

## 七、可访问性

1. **键盘**：所有交互控件 Tab 可达；Tab 顺序 = 视觉阅读顺序（左→右、上→下）；向导内左右方向键切换类型；对话框打开后焦点落在首个按钮，Esc = 取消。
2. **对比度**：正文 / 次要文字 / 标签文字对底色 ≥ 4.5:1（状态标签配色见 2.2/2.3）；主按钮白字对 `#4F46E5` = 5.9:1 达标。
3. **焦点可见**：聚焦控件 2px Primary 外描边（focus ring），偏移 2px。
4. **缩放**：窗口 1180×760 起，最小 960×640；内容区 `ScrollViewer` 纵向滚动，不截断。
5. **动效尊重**：后续迭代接入 `SystemParameters.MinimizeAnimation`/减少动效偏好检测，提供"减少动画"开关。

## 八、与《项目开发规范》第七章对照（验收映射）

| 规范条款 | 设计方案落点 |
| --- | --- |
| 7.1 页面零内联模糊 | 四个视图全部只引用 `BlurCardStyle` / `BlurDialogStyle` / `BlurPanel.*`，无一处 `<BlurEffect>` 内联 |
| 7.2 字典组织与顺序 | 设计令牌即现有 9 个字典，加载顺序 = `Styles.xaml` 现状 |
| 7.3 模糊档位 | 2.6 表与 `Sizes.xaml` 键一一对应 |
| 7.4 BlurPanel 组件 | 卡片 / 对话框 / 侧边栏三处复用同一组件，页面零模糊细节 |
| 7.5 引用规则 | 主题相关一律 DynamicResource；档位与几何 StaticResource |
| 7.6 圆角动画全局化 | 2.5 / 五·入场动画全部来自 `Sizes.xaml` / `Animations.xaml` |
| 7.7 性能红线 | 列表项无独立模糊；动画只动 Opacity/Transform；静态层 BitmapCache |
| 7.8 主题联动 | 浅/深键名一一对应，覆盖层色 DynamicResource 引用 |
| 7.9 验收清单 | 第七、八节即可访问性与性能侧的设计侧承诺 |

## 九、对现有实现的改进建议（按优先级）

1. **列表卡片信息升级**（P1）：现列表仅"名称 + 双标签 + 打开"。建议补进度条与更新时间，详情入口改「打开」文案，与 4.1 对齐。
2. **向导类型选择步骤**（P1）：现 Wizard 直接进表单。建议增加三卡片类型选择步，与 4.2 对齐（剪辑/待办字段亦按此扩展）。
3. **状态标签配色**（P1）：由实色底白字改为浅底深字 / 深色主题半透明底，满足 AA 对比（2.2/2.3）。
4. **详情页两栏 + 进度卡片**（P2）：现为单栏长表单，建议按 4.3 分区卡片化。
5. **设置页预览化**（P2）：主题与模糊改为带即时预览的卡片选择，替代纯下拉。
6. **Toast 轻提示组件**（P2）：新增全局 Toast（磨砂 + SlideUp 动画），承载"已保存"等成功反馈。
