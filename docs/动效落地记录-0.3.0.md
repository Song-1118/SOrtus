> 落地版本：0.3.0（动效是 0.3.0 的主题，与 VD-062~068 同批）

## 一、这次做了什么

规范 §1 的结论是「缺的不是动画，是节奏系统」。因此本次落地分三层：

1. **令牌层**（`Resources/Styles/Animations.xaml`）：新增 `Std / Enter / Exit / Back` 四种缓动与
   `D-80 / D-120 / D-180 / D-240 / D-320 / D-600` 六档时长的用法注释；所有条目只引用令牌值，
   规范禁止的「随手 130ms」在文件里不存在。
2. **接线层**（新增 `Controls/Motion.cs`）：统一注入 `RenderTransform`、统一播放入口、统一
   「减少动效」降级、统一动画计数。规范 §7 明确「Storyboard 写死 RenderTransform 时元素没有
   对应变换就静默不动」——这个坑由 `Motion` 一次性解决，页面只声明意图。
3. **断言层**（新增 `build/check_animation_wiring.py`）：要求 `Animations.xaml` 里每个 `x:Key`
   至少被引用一次。VD-062 的原始事故就是「3 组 Storyboard 全仓 0 引用」，此脚本把那次事故变成
   可自动拦截的回归。

## 六、本轮修掉的两个真实缺陷

- **确认弹窗主按钮整颗消失**：页面内联 `<Style TargetType="local:SOrButton">` 顶掉了隐式样式，
  控件失去模板。规范落地时又踩了一次同一个坑（`BasedOn="{StaticResource {x:Type local:SOrButton}}"`
  在 `ViewTemplates` 字典内不可见 → `XamlParseException`，冒烟直接崩）。正确做法统一为：
  **需要页面定制的控件样式，一律在控件字典里定义 keyed 样式，再让页面字典合并该控件字典。**
- **截图 07 文档弹窗空白**：破坏性确认弹窗的 150ms 退场动画没走完就开下一个弹窗，
  `DialogService` 同一时刻只承载一个覆盖层，新弹窗被吞。截图顺序已调整为先文档弹窗、后确认弹窗。
