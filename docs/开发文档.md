## 一、项目概述

### 1.1 项目背景

个人或小型团队在启动一个项目时，往往缺乏一个轻量、统一的地方来沉淀立项信息、跟踪开发/制作进度、管理约束与目标。散落在聊天记录、备忘录、表格中的信息难以复用，项目过程中也缺少可视化的进度反馈。

SOrtus 旨在提供一个**本地优先、开箱即用**的立项管理小工具，用统一入口管理不同类型的"立项"。

### 1.2 项目定位

| 维度 | 说明 |
| --- | --- |
| 项目名称 | SOrtus（S-Super/Song宋，Ortus-起源，即"项目的起源"） |
| 一句话简介 | 用一个小工具管理您的立项 |
| 项目类型 | Windows x64 桌面应用 |
| 开源协议 | MIT |
| 分发模式 | 完全本地运行，单机版 |

### 1.3 设计原则与核心约定

1. **本地优先**：所有数据保存在本机 SQLite 中，不外传。
2. **无后端**：不预留任何远端接口，不开发后端服务器。
3. **纯净体验**：不考虑收费、会员、广告，不植入任何形式的商业变现模块。
4. **面向立项**：聚焦"立项—执行—验收"这一完整闭环，而非泛化的任务管理。
5. **现代体验**：控件高斯模糊、圆角、现代动画与平滑动画，强调视觉质感与交互流畅度。
6. **可定制**：高斯模糊强度可调，至少两套主题，支持多语言（前期中英，后期扩展韩日）。
7. **可迁移**：提供基于 `.json` 的数据导出、导入与备份能力，方便迁移与恢复。

### 1.4 目标用户

- 独立开发者、编程学习者（编程开发项目立项）
- 视频创作者、剪辑师、短视频/微电影/纪录片制作者（剪辑项目立项）
- 需要管理日常任务与提醒的个人（待办类型立项）

### 1.5 立项类型总览

SOrtus 支持三类立项，立项时采集核心信息，立项后可持续维护与跟踪：

| 立项类型 | 立项时采集 | 立项后管理 |
| --- | --- | --- |
| 编程开发项目 | 项目名字、技术栈（选择+自定义）、简介、类型、关联文件夹（远期支持关联SSH）、开发工期 | 项目名称/技术栈/简介/类型/关联文件夹、开发规划、开发约束、开发目标、验收标准、Git 提交/推送/回退、项目版本、发行、开发进度 |
| 剪辑项目 | 项目主题、名字、目标时长、类型（Vlog/教程/微电影/纪录片/自定义）、预计工期 | 剪辑进度、拍摄进度、素材管理、关联素材文件夹 |
| 待办 | 任务、完成时间 | 是否完成、提醒 |

## 二、技术栈

### 2.1 核心技术选型

| 层级 | 技术 | 说明 |
| --- | --- | --- |
| 运行时 | .NET 10 LTS | 长期支持版本，保证生命周期内的稳定维护 |
| 语言 | C# 14 | 使用最新语言特性（集合表达式、扩展成员、nameof 增强等） |
| 表现层 | WPF（Windows Presentation Foundation） | 成熟的桌面 UI 框架，支持自定义控件、数据绑定、动画、模糊效果 |
| 长期存储 | SQLite | 单文件嵌入式数据库，零配置、可移植，适合本地数据长期保存 |
| 数据访问 | Microsoft.Data.Sqlite + Dapper / EF Core（待定） | 轻量 SQL 映射或 ORM，二选一 |
| 序列化 | System.Text.Json | 用于 `.json` 格式的导出/导入/备份 |
| 本地化 | .NET 资源文件（.resx / IStringLocalizer） | 中英双语，预留韩日扩展点 |
| 构建 | MSBuild / dotnet CLI | 标准 .NET 构建体系 |

### 2.2 关键技术点

- **高斯模糊**：基于 WPF `BlurEffect` 或 Win32 `DwmEnableBlurBehindWindow` / 自定义 `ShaderEffect`，参数可在设置中调节强度。
- **圆角与阴影**：自定义 `Border`/`Window` 样式，使用 `CornerRadius`、`DropShadowEffect` 与透明背景。
- **现代动画**：基于 `Storyboard` + `DoubleAnimation`、`EasingFunction`（CubicEase / BackEase 等）实现页面切换、控件状态过渡的平滑动画。
- **数据持久化**：SQLite 单文件数据库，配合轻量迁移脚本管理表结构演进。
- **Git 集成**：通过 LibGit2Sharp 或调用本地 git 命令行实现提交/推送/回退（编程类型项目）。

### 2.3 环境与依赖

- 目标框架：`net10.0-windows`
- 目标平台：`x64`，Windows 10/11
- 运行依赖：.NET 10 桌面运行时（可选自带发布 `self-contained`）
- 外部依赖原则：仅引入必要的 NuGet 包，避免引入网络/云服务类库。

## 三、架构设计

### 3.1 总体架构

采用**分层架构 + MVVM 模式**，保证界面与业务逻辑解耦，便于测试与维护。整体分四层：

```
┌─────────────────────────────────────────┐
│  View 层（WPF XAML）                     │
│  窗口 / 页面 / 自定义控件 / 动画 / 主题   │
├─────────────────────────────────────────┤
│  ViewModel 层（MVVM）                    │
│  RelayCommand / INotifyPropertyChanged   │
│  立项列表VM / 编程立项VM / 剪辑立项VM /    │
│  待办VM / 设置VM / 导出导入VM             │
├─────────────────────────────────────────┤
│  业务服务层（Service）                    │
│  立项服务 / 进度服务 / 提醒服务 /         │
│  Git服务 / 导出导入服务 / 主题语言服务    │
├─────────────────────────────────────────┤
│  数据访问层（Repository + SQLite）        │
│  立项仓储 / 字段扩展仓储 / 备份还原       │
└─────────────────────────────────────────┘
```

### 3.2 分层职责

| 层级 | 职责 | 关键依赖 |
| --- | --- | --- |
| View | 纯界面展示、用户输入、动画与视觉样式 | WPF、XAML、资源字典 |
| ViewModel | 状态管理、命令绑定、与界面无关的业务协调 | CommunityToolkit.Mvvm（或手写） |
| Service | 核心业务逻辑（立项CRUD、进度计算、Git操作、导出导入、提醒调度） | 仓储接口 |
| Repository | SQLite 读写、表结构管理、数据映射 | Microsoft.Data.Sqlite |

### 3.3 模块划分

- **立项核心模块**：统一立项实体基类 + 三种派生类型（编程 / 剪辑 / 待办），共用名称、创建时间、类型、状态等字段，差异化字段通过扩展表或 JSON 列承载。
- **存储模块**：SQLite 连接管理、表结构迁移、事务封装。
- **视图模块**：主窗口、立项向导（立项时采集）、立项详情页、列表页、设置页。
- **主题与视觉模块**：多套主题资源字典（浅色/深色等）、高斯模糊行为附加属性、动画资源。
- **本地化模块**：资源文件 + 语言切换服务。
- **导出导入模块**：序列化为 `.json`，支持全量导出/导入、单立项导出、备份与恢复。
- **Git 集成模块**（编程类型）：提交、推送、回退操作封装，调用本地 Git。
- **提醒模块**（待办类型）：基于定时器/计划任务的到期提醒。

### 3.4 数据模型（核心实体）

```
Project（立项基类）
├── Id, Name, Type(编程/剪辑/待办), Status, CreatedAt, UpdatedAt
├── 编程开发项目 : 技术栈, 简介, 关联文件夹, 工期, 开发规划, 约束, 目标, 验收标准, 版本, 发行, 进度
├── 剪辑项目 : 主题, 目标时长, 剪辑类型, 预计工期, 剪辑进度, 拍摄进度, 素材, 素材文件夹
└── 待办 : 任务描述, 完成时间, 是否完成, 提醒设置
```

### 3.5 技术决策记录（ADR 摘要）

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| UI 框架 | WPF | Windows 桌面原生，动画/样式/自定义控件能力强 |
| 数据库 | SQLite | 单文件、零配置、易备份迁移，契合本地优先 |
| 架构 | MVVM | 解耦界面与逻辑，便于单元测试与维护 |
| 网络 | 无 | 明确不预留远端接口，避免复杂度与隐私风险 |
| 商业化 | 无 | 不考虑收费/会员/广告，保持工具纯粹性 |

## 六、验收标准

### 6.1 总验收标准

> 项目整体交付须满足以下标准方视为完成。

1. **功能完整性**：三类立项（编程开发 / 剪辑 / 待办）的全部 P0、P1 功能可正常使用，覆盖立项时采集与立项后管理的完整闭环。
2. **技术符合性**：技术栈严格为 `.NET 10 LTS + C# 14 + WPF + SQLite`，目标平台为 Windows x64，可成功构建并运行。
3. **架构符合性**：代码分层清晰（View / ViewModel / Service / Repository），遵循 MVVM 模式，无明显业务逻辑混入 View 层。
4. **数据正确性**：所有立项数据的创建、读取、更新、删除（CRUD）准确无误，SQLite 存储持久化正常，重启后数据不丢失。
5. **数据迁移能力**：支持 `.json` 格式的全量/单立项导出与导入，备份可恢复，导入后数据一致。
6. **视觉与体验**：控件高斯模糊（强度可调）、圆角、至少两套主题、现代动画与平滑动画均已实现，界面交互流畅无卡顿。
7. **多语言**：中英文界面切换正常，所有可见文本走资源文件；韩文、日文扩展点已预留。
8. **核心约定遵守**：无任何远端接口、无后端服务器、无收费/会员/广告模块，应用纯本地运行。
9. **Git 集成（编程类型）**：在合法 Git 仓库路径下，提交、推送、回退操作可正常执行，错误有明确提示。
10. **质量与稳定性**：主流程无未处理异常，关键业务有单元测试覆盖，可复现崩溃有日志记录。
11. **文档与许可**：开发文档、PRD 文档、使用说明齐全；仓库包含 `LICENSE`（MIT）文件。
12. **可发布性**：可成功打包为 x64 应用，在 Windows 10/11 上安装/运行正常。

### 6.2 各阶段验收标准

#### M1 验收标准

- 解决方案可成功编译，运行后显示主窗口骨架与导航框架。
- 分层目录结构清晰，四层职责划分明确。
- SQLite 数据库文件在首次运行时自动创建，立项基表存在。
- 表结构迁移机制可正常运行（从无到有、版本升级场景）。

#### M2 验收标准

- 可完成一个编程开发项目的完整立项流程（向导采集全部立项时字段）。
- 立项列表可正确展示、按类型/状态筛选、搜索。
- 详情页可查看并编辑立项后字段（开发规划/约束/目标/验收标准/进度等）。
- 数据写入 SQLite 后重启应用不丢失。

#### M3 验收标准

- 可完成剪辑项目的完整立项与管理（主题/名字/时长/类型/工期、剪辑进度、拍摄进度、素材、素材文件夹）。
- 可完成待办类型的完整立项与管理（任务/完成时间、是否完成、提醒设置）。
- 三类立项在同一列表中可正确区分、差异化展示与编辑，互不干扰。

#### M4 验收标准

- 高斯模糊可全局调节强度，设置生效并持久化。
- 至少两套主题可运行时切换，切换后全局样式一致无残留。
- 控件圆角、阴影、动画（页面切换/状态过渡）正常，无明显掉帧。
- 中文 / 英文界面切换正常，全部文本走资源；韩文、日文资源扩展点已预留。

#### M5 验收标准

- 全量导出 `.json` 内容完整、格式合法，可被工具重新导入。
- 单立项导出/导入正常，导入时可选择覆盖或合并策略。
- 备份可成功生成并在清空数据后恢复，数据一致。
- 编程类型关联文件夹为合法 Git 仓库时，提交/推送/回退操作可用，失败有明确错误提示。
- 项目版本与发行信息可管理与展示。

#### M6 验收标准

- 待办到期提醒按设置正常触发（当天/提前 N 分钟）。
- 全部 P0/P1 功能通过集成测试与回归，主流程无阻断性缺陷。
- 开发文档、PRD、使用说明均完整并与实际功能一致。
- 应用成功打包为 x64 安装包/便携版，在 Windows 10/11 上可正常安装运行。
- 仓库根目录包含 `LICENSE`（MIT）文件，版权声明正确。
- 全量导出一份 `.json` 备份，作为发布配套资料。
